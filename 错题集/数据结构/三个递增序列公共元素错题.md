## 题目

```
给定长度均为 n 且无重复元素的递增序列 A、B、C，逐行输出同时存在于
三个序列中的所有元素。例如 A={1,2,3}、B={2,3,4}、C={-1,0,2}，输出 2。
要求：给出基本设计思想；用 C 或 C++ 描述算法并在关键处注释；
分析时间复杂度和空间复杂度。
```

（算法设计题，无选项。三个序列均为「长度相等、无重复、严格递增」的顺序表。）

## 基本设计思想

三个序列都严格递增且无重复，因此可以像归并一样用三个游标 `i、j、k` 同时扫描：

1. 每次比较当前三个元素 `A[i]、B[j]、C[k]`。
2. 若三者相等，说明该值同时出现在三个序列中，输出并同时后移三个游标。
3. 若不全相等，则**最小者所在序列的游标前移一位**——因为它是三者中最小的当前值，而其他序列的当前值都比它大；由于序列严格递增且无重复，该最小值在另外两个序列的「未扫描部分」中不可能再出现（另外两个序列当前位置已大于它，后面只会更大），所以它可以被安全淘汰。
4. 任一游标越界即结束（三序列等长，实际会同时结束，但写成任一越界即止更稳健）。

关键点在于「淘汰最小值」的正确性：**递增**保证被淘汰的值不会再出现，**无重复**保证同一序列内不会因跳过一个相等值而漏判。

## 参考算法（C/C++）

```c
// A、B、C 为长度均为 n 的递增有序数组（无重复元素）
void PrintCommon(int A[], int B[], int C[], int n) {
    int i = 0, j = 0, k = 0;              // 三个游标，分别指向当前待比较元素
    while (i < n && j < n && k < n) {     // 任一序列扫描完即结束
        if (A[i] == B[j] && B[j] == C[k]) {
            printf("%d\n", A[i]);         // 三值相等：公共元素，逐行输出
            i++; j++; k++;                // 三者同步后移
        } else if (A[i] <= B[j] && A[i] <= C[k]) {
            i++;                          // A[i] 是当前最小值，不可能再匹配，淘汰
        } else if (B[j] <= A[i] && B[j] <= C[k]) {
            j++;                          // B[j] 最小，淘汰
        } else {
            k++;                          // 否则 C[k] 最小，淘汰
        }
    }
}
```

> 说明：分支里的 `<=` 可以写成 `<`，因为三值不全相等时「最小值」不会同时出现在两个序列的当前位置上（若 `A[i]==B[j]<C[k]`，两种写法都只会推进一个游标，不影响正确性；用 `<=` 只是让分支判定更直白）。

**正确性论证**：

- 不变式：`A[0..i-1]、B[0..j-1]、C[0..k-1]` 中已不存在尚未输出的公共元素。
- 每次淘汰最小值 `x`：另两个序列当前位置的值都 ≥ x；若 > x，则 x 不可能再出现（递增）；若 = x，则 x 只在其中一个序列当前位置出现，另一个序列当前位置更大，同理 x 不可能成为三者公共值。故淘汰安全。
- 三值相等时立即输出：由于无重复，该值在三个序列中各只出现一次，不会重复输出。

## 复杂度分析

- **时间**：每轮循环至少有一个游标前进 1，三个游标总共最多前进 `3n` 次，故 `O(n)`。相比「两两求交再求交」的多次扫描，常数更小且只扫描一遍。
- **空间**：只用 3 个游标变量和常数个临时变量，除输出外无辅助数组，`O(1)`。

**与常见错误解法的对比**：

| 解法 | 时间 | 空间 | 问题 |
| --- | --- | --- | --- |
| 三重循环枚举 | O(n³) | O(1) | 完全没利用有序性 |
| 对 A 的每个元素在 B、C 中各二分 | O(n log n) | O(1) | 可行但不是最优，常数大 |
| 先求 A∩B 存数组，再与 C 求交 | O(n) | O(n) | 辅助数组破坏 O(1) 空间 |
| **三指针同步扫描（本题）** | **O(n)** | **O(1)** | 最优 |

## 根因分析

未作答，属首次接触「多路归并 + 公共元素」题型。易错点集中在：

1. **只想到两两求交**：先算 A∩B 再与 C 求交，虽然也是 O(n)，但需要额外数组，空间退化到 O(n)，且写两遍重复逻辑。
2. **淘汰规则记错**：误以为「不相等就全部后移」→ 会漏掉公共元素；或误以为「只移动最大者」→ 会死循环（最大值不动，其余推进后仍可能不相等，最终越界但效率退化，甚至逻辑颠倒）。
3. **忽略「递增」这一前提**：若序列无序，淘汰最小值就不成立，必须改用哈希集合求交，时间 O(n)、空间 O(n)。
4. **忽略「无重复」这一前提**：若有重复，同一公共值会被输出多次，需要额外去重（例如记录上一次输出的值）。
5. **边界处理**：三序列等长时用 `i<n && j<n && k<n` 即可；若长度不等，必须用各自长度做上界，否则越界。

## 完整知识点梳理

**多路归并（k-way merge）思想**：把 k 个有序序列的扫描过程统一到「每步比较 k 个当前元素、推进其中一个或多个游标」的框架。它是有序表相关算法题的总模板。

| 题型 | 游标推进规则 | 复杂度 |
| --- | --- | --- |
| 两有序表合并 | 取较小者写入结果，该游标 +1 | O(m+n) / O(m+n) |
| 两有序表求交 | 相等则输出并双 +1；否则小者 +1 | O(m+n) / O(1) |
| 两有序表求差（A−B） | 相等双 +1 且不输出；A 小则输出 A 并 +1；否则 B +1 | O(m+n) / O(1) |
| **三有序表求交（本题）** | **三值相等则输出并三 +1；否则最小者 +1** | **O(n) / O(1)** |
| k 路归并排序的合并阶段 | 用堆取 k 路最小者 | O(N log k) |

**判定法则（考场速记）**：

1. 看到「有序 + 求交集/并集/差集」→ 立刻想到双（多）指针，目标 O(n)、O(1)。
2. 求交：**相等才输出，否则淘汰较小者**；求并：**每次输出较小者并去重**；求差：**相等时双方都跳过**。
3. 淘汰方向永远是「小的走」，因为大的还可能匹配后面更大的值。
4. 「无重复」是用「相等即输出」而不需要去重的前提；题目若去掉这个条件，必须补充去重逻辑。
5. 多路时边界用「任一越界即停」，不要假设所有序列等长。

**输出格式注意**：题目要求「逐行输出」，即每个公共元素后跟换行（`printf("%d\n", ...)`）；若要求「输出个数」则应单独计数。

**记忆口诀**：

> **「三针同扫，相等齐走；不等淘汰最小，越界即收。」**

## 复刷清单

### 举一反三 5 题

1. 【单选】三个长度均为 n 的递增无重复序列求公共元素，最优算法的时间复杂度是（ ）。
   A. O(n)　B. O(n log n)　C. O(n²)　D. O(n³)
   **答案：A**。三指针每轮至少推进一个游标，总推进次数 ≤ 3n。

2. 【单选】三指针扫描中，当 `A[i] < B[j]` 且 `A[i] < C[k]` 时，正确的操作是（ ）。
   A. 输出 A[i] 并三个游标都后移
   B. 只将 i 后移
   C. 只将 j、k 后移
   D. 结束循环
   **答案：B**。A[i] 是当前最小值，另外两个序列当前位置都更大，A[i] 不可能再成为公共元素，故淘汰它。

3. 【单选】若把题目条件「递增」去掉，仅保留「无重复」，求三序列公共元素最高效的通用做法是（ ）。
   A. 三指针扫描，O(n)、O(1)
   B. 把 A、B 放入哈希集合，再遍历 C 判断，O(n)、O(n)
   C. 三重循环，O(n³)、O(1)
   D. 先对三个序列排序，O(n log n)
   **答案：B**。无序时「淘汰最小值」不再成立，需用集合做成员判断；时间 O(n)、空间 O(n)。

4. 【单选】若三个序列**允许重复元素**，在上述三指针算法中直接「相等即输出」会导致（ ）。
   A. 死循环
   B. 同一公共值被重复输出
   C. 漏掉公共元素
   D. 数组越界
   **答案：B**。例如 A={2,2}、B={2,2}、C={2,2} 会输出 4 次 2；需要记录上次输出值或先去重。

5. 【单选】三序列长度不等分别为 m、n、p 时，循环条件应写为（ ）。
   A. `i<m && j<n && k<p`
   B. `i<n && j<n && k<n`
   C. `i<m || j<n || k<p`
   D. `i<=m && j<=n && k<=p`
   **答案：A**。每个游标用各自长度做上界，任一越界即结束；C 会导致越界访问。

### 历年真题风格练习

1. 【统考风格·算法设计】有两个长度分别为 m、n 的递增有序顺序表 A、B，设计算法求它们的交集并存入 A 中（原地），要求时间 O(m+n)、空间 O(1)，写出算法并分析复杂度。
   **答案**：`i` 扫 A、`j` 扫 B、`k` 记交集长度；`A[i]==B[j]` 时 `A[k++]=A[i]`，`i++`、`j++`；`A[i]<B[j]` 时 `i++`；否则 `j++`。结束后 `A.length=k`。时间 O(m+n)，空间 O(1)。

2. 【统考风格·算法设计】给定三个递增有序顺序表，设计算法输出**只出现在 A、B 中但不在 C 中**的元素，要求 O(n)、O(1)。
   **答案**：三指针；当 `A[i]==B[j]` 时再看与 `C[k]` 的关系：若 `A[i]<C[k]` 则输出 `A[i]` 并 `i++`、`j++`；若 `A[i]==C[k]` 则三者同进且不输出；若 `A[i]>C[k]` 则 `k++`。当 `A[i]<B[j]` 时 `i++`，否则 `j++`。每轮至少推进一个游标，O(n)。

3. 【统考风格·复杂度分析】若用「对 A 中每个元素在 B、C 中各做一次二分查找」求三序列公共元素，时间复杂度是多少？与三指针法相比有何优劣？
   **答案**：每次二分 O(log n)，共 n 个元素、两次查找，时间 O(n log n)；空间 O(1)。三指针法 O(n) 更优，且缓存友好；二分法胜在实现简单、可用于「一个序列很短、另一个极长」的不等长场景。
