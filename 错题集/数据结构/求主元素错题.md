## 题目

```
已知一个整数序列 A = (a0, a1, …, a(n-1))，其中 0 ≤ ai < n (0 ≤ i < n)。
若存在 ap1 = ap2 = … = apm = x 且 m > n/2 (0 ≤ pk < n, 1 ≤ k ≤ m)，
则称 x 为 A 的主元素。例如 A = (0,5,5,3,5,7,5,5)，则 5 为主元素；
又如 A = (0,5,5,3,5,1,5,7)，则 A 中没有主元素。
假设 A 中的 n 个元素保存在一个一维数组中，请设计一个尽可能高效的算法，
找出 A 的主元素。若存在主元素，则输出该元素；否则输出 -1。
要求：
(1) 给出算法的基本设计思想。
(2) 根据设计思想，采用 C、C++ 或 Java 语言描述算法，关键之处给出注释。
(3) 说明算法的时间复杂度和空间复杂度。
```

（算法设计题，无选项。这是 2013 年统考真题。）

## 基本设计思想

主元素的出现次数**严格超过 n/2**，这给出两个关键性质：

1. **候选唯一性**：若主元素存在，它出现次数超过其余所有元素之和，因此两两不同的元素互相抵消后，最后剩下的候选只可能是主元素。
2. **必须验证**：候选也可能不存在（例如所有元素各出现一次），所以第二遍必须统计候选的真实出现次数，超过 n/2 才确认。

因此采用**两遍扫描（Boyer-Moore 投票思想的简化版）**：

- **第一遍**：用 `count` 记录候选出现次数。遇到与当前候选相同的元素则 `count++`，不同则 `count--`；`count` 减到 0 时把当前元素换为新候选。扫描结束时 `c` 为主元素候选。
- **第二遍**：再扫描一遍统计 `c` 的实际出现次数 `num`。若 `num > n/2`，输出 `c`；否则输出 `-1`。

**为什么第一遍能找到正确候选**：把出现次数超过 n/2 的元素记为 x、其余元素记为「非 x」。每次 `count--` 表示一个 x 与一个非 x「抵消」。由于 x 的数量严格大于其余元素之和，抵消完所有非 x 后至少还剩一个 x，最终候选必为 x。若主元素不存在，第一遍只会得到一个任意候选，由第二遍过滤掉。

## 参考算法（C）

```c
int Majority(int A[], int n) {
    int i, c, count, num = 0;
    c = A[0];                        // 初始候选取首元素
    count = 1;                       // 候选相对计数
    for (i = 1; i < n; i++) {        // 第一遍：找候选
        if (A[i] == c)
            count++;                 // 遇到候选，计数加 1
        else if (count > 0)
            count--;                 // 遇到不同元素，计数减 1（抵消）
        else {
            c = A[i];                // 计数减到 0，更换候选
            count = 1;
        }
    }
    for (i = 0; i < n; i++)          // 第二遍：统计候选真实出现次数
        if (A[i] == c)
            num++;
    if (num > n / 2)                 // 超过一半才确认是主元素
        return c;                    // 找到主元素
    return -1;                       // 不存在主元素
}
```

**主元素一定存在的简化情形**：若题目保证主元素必存在（如选择题常考「序列中必有一个元素出现次数超过一半」），可省去第二遍验证，直接输出候选，时间仍 O(n)、空间 O(1)。

## 复杂度分析

- **时间**：第一遍扫描 n 次，第二遍最多再扫 n 次，总比较次数 ≤ 2n，故 O(n)。相比排序法 O(n log n) 和哈希法，是时间最优且不需额外数组。
- **空间**：只用候选 `c`、计数 `count`、真实计数 `num` 三个变量，O(1)。

**与常见解法的对比**：

| 解法 | 时间 | 空间 | 特点 |
| --- | --- | --- | --- |
| 两遍扫描（本题） | O(n) | O(1) | 最优；利用主元素「超过半数」性质 |
| 排序后取中位数验证 | O(n log n) | 取决于排序 | 若主元素存在必占中位数位置，仍需验证 |
| 哈希计数 | O(n) | O(n) | 空间换直观，不满足 O(1) 要求 |
| 两两抵消（递归分治） | O(n) | O(log n) 或 O(1) 迭代 | Boyer-Moore 原始形式，思路相同 |

## 根因分析

未作答，属首次接触主元素 / 摩尔投票题型。易错点集中在：

1. **直接排序取中位数**：思路可行但时间 O(n log n)，且题目要求「尽可能高效」，不是最优。
2. **用哈希表计数**：时间 O(n) 但空间 O(n)，若题目明确 O(1) 空间则不合规。
3. **只找候选不做第二遍验证**：当主元素不存在时会错误输出候选（例如 `(1,2,3,1,2)` 第一遍候选可能是 1 但只出现 2 次 ≤ n/2）。
4. **验证条件写错**：写成 `num >= n/2` 或 `num > n/2` 弄混。定义是 m > n/2，**必须严格大于**；n 为偶数时 n/2 不算过半。
5. **更换候选时机写错**：应在 `count == 0` 时才换新候选；若在 `count` 仍大于 0 时遇到不同元素就换候选，会破坏抵消逻辑。
6. **忽略「0 ≤ ai < n」条件的作用**：它暗示可以用长度 n 的计数数组（桶计数）替代哈希，但那仍是 O(n) 空间；本题最优解不需要该数组。

## 完整知识点梳理

**摩尔投票（Boyer-Moore Majority Vote）核心模板**：

```
候选 c ← 首元素，count ← 1
从第 2 个元素开始扫描：
    A[i] == c    → count++
    count > 0    → count--
    否则         → c ← A[i], count ← 1
```

**判定法则（考场速记）**：

1. 「出现次数超过一半」→ 摩尔投票，两遍扫描：找候选 + 验证。
2. **候选唯一性**由「超过一半」保证：主元素数量 > 其余元素之和，抵消后必然存活。
3. **验证不可省略**：除非题目保证主元素必存在。
4. 判定条件是 **m > n/2（严格大于）**，n 为偶数时恰好 n/2 不算主元素。
5. 若题目问「出现次数超过 n/3」的元素，则最多 2 个，需要维护两个候选和两个计数（扩展版摩尔投票）。
6. 若题目问「出现次数超过 n/k」，最多 k−1 个候选，同理扩展。

**与本题相关的变式**：

| 变式 | 解法 | 复杂度 |
| --- | --- | --- |
| 找出现次数超过一半的元素（必存在） | 一遍摩尔投票，直接输出候选 | O(n) / O(1) |
| 找超过一半元素（不一定存在） | 两遍摩尔投票 | O(n) / O(1) |
| 找出现次数超过 n/3 的元素 | 双候选摩尔投票 | O(n) / O(1) |
| 只判断是否存在主元素 | 同本题，返回布尔值 | O(n) / O(1) |

**记忆口诀**：

> **「同则加一，异则抵一，零则换候选；终选再数一遍，过半才算数。」**

## 复刷清单

### 举一反三 5 题

1. 【单选】求主元素的两遍扫描算法中，第一遍扫描结束时得到的 `c` 是（ ）。
   A. 一定是主元素
   B. 一定不是主元素
   C. 可能的主元素候选，还需第二遍验证
   D. 出现次数最多的元素
   **答案：C**。第一遍只保证「若主元素存在则候选必为它」；主元素不存在时候选是任意值，必须验证。

2. 【单选】若主元素存在，第一遍扫描中「相同加一、不同减一、减到零换候选」的操作为什么能保证主元素成为最终候选？（ ）
   A. 因为数组已有序
   B. 因为主元素出现次数超过其余元素之和，抵消后仍有剩余
   C. 因为计数不会为负
   D. 因为候选更换次数不超过 n/2
   **答案：B**。每次 `count--` 相当于一个主元素与一个非主元素抵消，主元素数量严格更多，抵消不完。

3. 【单选】验证候选时，判断「是主元素」的正确条件是（ ）。
   A. `num >= n/2`
   B. `num > n/2`
   C. `num > n/2 - 1`
   D. `num == n/2`
   **答案：B**。定义 m > n/2，严格大于；A 在 n 为奇数时与 B 等价，但 n 为偶数时 n/2 不算主元素。

4. 【单选】对序列 `(1,2,3,1,2)`，两遍扫描算法的输出是（ ）。
   A. 1
   B. 2
   C. 3
   D. -1
   **答案：D**。第一遍候选可能是 1（出现 2 次），但 2 ≤ n/2 = 2.5，验证失败输出 -1。注意 n=5 时 n/2=2（整除），2 > 2 不成立。

5. 【单选】若题目改为「找出出现次数超过 n/3 的所有元素」，最优算法最多需要维护几个候选？（ ）
   A. 1 个
   B. 2 个
   C. 3 个
   D. n/3 个
   **答案：B**。超过 n/3 的元素最多 2 个（若有 3 个，总数将超过 n），用双候选摩尔投票即可。

### 历年真题风格练习

1. 【统考真题·2013】本题原型：设计尽可能高效的算法找出主元素，不存在输出 -1。
   **答案**：即上述两遍扫描法，O(n)/O(1)。

2. 【真题改编】若题目保证序列中一定存在主元素，算法应如何简化？复杂度是多少？
   **答案**：省去第二遍验证，第一遍结束直接输出候选；时间 O(n)、空间 O(1)。

3. 【真题改编】若不允许修改数组且要求空间 O(1)，但序列中元素范围不是 0..n-1 而是任意整数，两遍扫描法是否仍然适用？
   **答案**：适用。摩尔投票不依赖元素取值范围，只依赖「出现次数超过一半」这一计数性质；哈希/桶计数反而需要额外空间。
