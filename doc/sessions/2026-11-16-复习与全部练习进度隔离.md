# 2026-11-16 复习与全部练习进度隔离

## 问题

在 4318「开始复习」答了一题后，切到「全部练习」，同一道题也显示为已答；反过来也一样。用户要求两个入口的进度**完全独立**，互不影响。

## 根因

`错题集/data/ky.db` 的 `progress` 表被 `CHECK (id = 1)` 限制成单行，复习（`forceMode=0`）和巩固（`forceMode=1`）共用一个进度槽位：

- `saveProgressRow` 无论哪种模式都写 `id=1`，后写的覆盖先写的。
- `/api/progress` GET 只读 `id=1`，`answerResults` 也只过滤该行的 `roundId`。
- `resumeQuiz` 用 `p.forceMode` 反推模式，导致切到另一模式时直接恢复成上一模式的轮次和答题记录。

## 修改

- `错题集/ebbinghaus/server.js`
  - `progress` 表去掉 `CHECK (id = 1)`；启动时检测旧表 DDL，存在该约束就重建表并迁移原有行（`[migrate] progress 表已重建为复习/巩固双槽位`）。
  - `saveProgressRow` 按 `p.forceMode` 写槽位 `2`（巩固）或 `1`（复习），清空也只清对应槽位。
  - `loadDB` 同时读出 `db.progress`（id=1）和 `db.progressForce`（id=2）。
  - `/api/progress` GET 支持 `?force=0|1`，返回对应槽位及其 `answerResults`；路由改为 `startsWith` 以兼容查询串。
  - `/api/finish` 先按 `roundId` 找到所属槽位，再清理该槽位；幂等分支同样只清对应槽位。
  - `dedupeQuestionIds` 清理进度时遍历两个槽位。
- `错题集/ebbinghaus/app.js`
  - `loadProgress` 请求带 `?force=`，`clearProgress` 带上 `forceMode`。
  - `resumeQuiz` 不再用服务端返回值改写 `forceMode`，始终以用户点击的入口为准。
  - 删除不再使用的 `resumeMode` 变量。
- `错题集/tests/stats-drill.test.mjs`
  - 移除对旧「先读进度再清空」逻辑的断言，改为校验「按模式取进度槽位」和「恢复时不切换模式」。
- `AGENTS.md`
  - 数学条目新增：**LaTeX 反斜杠必须单层**，`\\neq` 会被前端还原成换行导致公式断裂，登记后必须无头浏览器确认渲染。

## 验证

无头浏览器（Playwright + 本机 Chrome）真实点击验证，无 `pageerror`：

| 步骤 | 结果 |
| --- | --- |
| 点击「开始复习」 | 队列 91 题，`forceMode=false` |
| 复习轮答 1 题后退出 | 复习槽位 `answerResults` 记录该题 |
| 点击「全部练习」 | 队列 130 题，`answered=0`，复习答过的那题在巩固轮未答（`reviewResult: undefined`） |
| 巩固轮答 1 题后退出 | 复习槽位仍是 1 条记录，未被污染 |
| 再次点击「开始复习」 | 恢复原轮次 `eb-1794793014328`，已答 1 题 |
| 再次点击「全部练习」 | 恢复原轮次 `eb-1794792906793`，已答 2 题 |

接口核对：`GET /api/progress?force=0` 与 `?force=1` 返回不同 `roundId` 和各自的答题记录。
